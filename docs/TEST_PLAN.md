# Local Media Manager Test Plan

> 本文档定义可重复的产品验收基线。每个版本根据功能范围执行适用用例，并把结果写入 `docs/releases/` 的版本验证报告。功能等价矩阵中的“已完整迁移”必须引用这里的自动化与人工验收证据。

## 1. 测试等级

| 等级 | 含义 | 发布要求 |
|---|---|---|
| ★★★★★ | 数据安全、启动、Bridge、Migration、核心用户状态 | 每个 Release 全部通过；失败阻止发布 |
| ★★★★☆ | 高频媒体管理与关键用户流程 | 涉及版本必须通过；回归抽样必须通过 |
| ★★★☆☆ | 体验、效率与次要工作流 | 目标版本通过；已发布功能做冒烟回归 |
| ★★☆☆☆ | 扩展、兼容和低频功能 | 功能启用时执行 |
| ★☆☆☆☆ | 实验或未来占位能力 | 不作为当前发布阻断项 |

## 2. 测试阶段

| 阶段 | 必做内容 |
|---|---|
| Self Test | 单元/集成测试、类型检查、静态检查、Bridge/Migration Debug 构建 |
| Smoke Test | 真实数据库、真实图片、独立安装版关键路径 |
| Freeze | 全量回归、缺陷分级、仅允许阻塞缺陷修复 |
| Release | Web/.NET/Tauri Debug/Release、NSIS、备份部署、安装升级、标签 |
| Archive | 固化报告、日志摘要、Commit、版本/回滚标签和未完成事项 |

## 3. 环境矩阵

### Windows 与显示

- Windows 当前受支持版本，x64。
- 深色主题、浅色主题。
- Windows 100%、125%、150% 缩放。
- 逻辑视口至少覆盖 1920×1080、1536×864、1280×720。
- Tauri 最小窗口 900×600。

### 数据规模

- 小型：空库、1 部、少于 1 页。
- 当前真实库：使用本地脱敏的大型样本，具体数量不写入公开报告。
- 中型性能样本：5 万部。
- LTS 压力样本：10 万部。

性能样本必须使用生成或脱敏数据，不复制用户私人媒体文件。

### 资源状态

- 数据库存在/不存在/只读/损坏副本。
- Bridge 正常、未启动、端口占用和中途退出。
- 媒体文件存在、缺失、无权限。
- 海报存在、缺失、损坏、横版和竖版。
- 网络在线/离线；云 Provider 默认关闭。

## 4. 发布阻断用例（★★★★★）

### TP-START 应用启动

- [ ] 安装版首次启动成功，标题、图标和版本正确。
- [ ] Bridge 随主程序启动并仅监听 loopback。
- [ ] Bridge 启动失败时页面显示可理解错误，不白屏或无限加载。
- [ ] 关闭并重新打开后核心页面可恢复使用。

### TP-BRIDGE Bridge

- [ ] `/health` 返回版本、数据库状态和只读/读写模式。
- [ ] DTO 字段与 TypeScript 类型一致。
- [ ] 无效参数返回明确 4xx；不存在资源返回 404；内部错误不泄露敏感路径或凭据。
- [ ] React 代码不存在 SQLite、文件系统或 Provider 直连。
- [ ] 写接口具备会话鉴权和输入校验后才能开放。

### TP-MIG Migration

- [ ] 迁移前备份源数据库并记录哈希。
- [ ] 临时库执行全部 checksummed Migration。
- [ ] `PRAGMA integrity_check` 为 `ok`，外键错误为 0。
- [ ] 迁移失败不替换当前正式库。
- [ ] 重复执行不重复写入，版本顺序和校验和异常可诊断。
- [ ] 抽样核对影片、收藏、评分、标签、演员、播放历史和图片关系。

### TP-FAVORITE 收藏

- [ ] 旧收藏标签正确映射到新收藏状态。
- [ ] 收藏和取消收藏真实写入 Bridge，卡片/详情/筛选计数同步。
- [ ] 重启后状态保持。
- [ ] 自动重命名关闭时不执行；失败时不撤销收藏。
- [ ] Bridge 失败时 UI 回滚乐观状态并提示。

### TP-RATING 评分

- [ ] 设置 1–5 星、清除评分并正确区分未评分和 0。
- [ ] 卡片、详情、排序和筛选即时一致。
- [ ] 重启后保持；批量或并发写入不丢失。
- [ ] 删除前评分记忆与同名恢复用例通过。

### TP-TAGS 标签

- [ ] 创建、重命名、删除自定义标签。
- [ ] 系统标签和收藏兼容标签不可被误删。
- [ ] 单部与批量绑定真实持久化，重启后保持。
- [ ] 删除前显示影响影片数量；失败可回滚。
- [ ] 损坏文字和重复名称有明确处理。

### TP-DELETED-RATING 删除评分记忆

- [ ] 删除时只保存“文件名 + 有效评分”和必要审计时间。
- [ ] 不保存完整路径、标签、收藏、备注等额外信息。
- [ ] 同名重新导入恢复评分。
- [ ] 新影片已有评分时禁止覆盖。
- [ ] 删除、导入或恢复中途失败时数据库保持一致。

### TP-ACTOR 演员关系

- [ ] 编辑演员关系后详情、演员页和计数一致。
- [ ] ActorID=0、空名和无效关系可以诊断。
- [ ] 修复先预览影响范围，经确认进入 Tasks。
- [ ] 修复不误删有效演员，可从备份或审计记录恢复。

### TP-PLAY 播放与历史

- [ ] 系统默认播放器和配置播放器均可启动。
- [ ] 只有启动成功才增加播放次数和历史。
- [ ] 启动失败不增加计数，并显示可理解错误。
- [ ] 最近播放顺序、时间和位置正确；重启保持。
- [ ] 上一部/下一部沿用原筛选、排序和结果集。

## 5. 高频媒体管理（★★★★☆）

### TP-MEDIA 影片墙

- [ ] 海报、番号、状态标签、日期、评分顺序正确。
- [ ] 长番号省略但 Tooltip 完整，日期只显示年月日。
- [ ] 点击卡片进入详情；播放 Hover 不阻断普通点击和键盘。
- [ ] 缺海报、缺文件和损坏数据有明确状态。

### TP-PAGING 分页

- [ ] 总页数使用筛选后总量计算。
- [ ] 首页、末页、上一页、下一页和直接页码跳转正确。
- [ ] 筛选、排序和每页数量变化回到第一页。
- [ ] 非法页码、0、负数和超大值被钳制并反馈。
- [ ] 跨页无重复或遗漏；稳定次排序通过。

### TP-SEARCH 搜索与筛选

- [ ] 番号、标题、演员、标签、路径、厂商和系列命中。
- [ ] 收藏、评分、日期、元数据、文件状态和媒体库筛选正确。
- [ ] 跨维度 AND、同维度多选 OR。
- [ ] 空关键词、特殊字符、Unicode 和损坏文本不会导致 SQL 错误。
- [ ] 普通搜索在 AI 关闭/不可用时仍完整工作。

### TP-LIBRARY 媒体库、扫描与导入

- [ ] 创建、编辑、启停和删除媒体库。
- [ ] 来源目录、子目录、排除规则和最近扫描时间正确。
- [ ] NFO、图片、字幕不被识别为影片。
- [ ] `.vob`、`.mpg`、`.mpeg` 等支持格式按规则识别。
- [ ] 单文件失败不终止批次；导入/更新/跳过/失败数量正确。
- [ ] 新增影片按设置进入同步任务。

### TP-SYNC 同步与 MetaTube

- [ ] 手工同步入口始终保留，自动同步是附加能力。
- [ ] 默认补空字段，不覆盖用户标题、标签、评分、收藏和图片锁定。
- [ ] MetaTube 结果按番号选择，来源、演员图和预览图分别记录。
- [ ] 精确番号结果优先，并按 `FANZA/MGS/JavBus/JAV321/AVBASE` 旧版顺序选择 Provider。
- [ ] Provider 地址、超时、图片、NFO 和自动执行设置经 Settings Service 保存，连接测试不隐式保存。
- [ ] 网络失败、无结果、部分字段失败不破坏旧数据。
- [ ] 图片使用临时文件原子落盘；失败只清理本次新文件，不删除已有图片/NFO。
- [ ] 批量同步进入 Tasks，可取消、重试并查看日志。
- [x] 只读协议预检：MetaTube `v1.4.0-c0e053f` 搜索 `ABP-001` 返回 8 条，FANZA 详情返回演员/类型/预览，主图返回 JPEG（92,237 字节）；2026-07-16，未写正式数据。
- [ ] 在数据库副本和专用图片/NFO 根目录，对固定 30–50 部样本完成真实写入烟测并保留逐部 before/after、Provider、任务和保护字段证据。

### TP-NFO NFO

- [ ] 导入/导出标题、简介、日期、演员、标签和图片引用。
- [ ] 图片、演员图、截图、预览图和覆盖行为使用独立设置。
- [ ] 样本往返后用户字段不丢失。
- [ ] 文件系统写入失败时数据库和旧 NFO 保持安全。

### TP-IMAGES 图片与卡图

- [ ] poster、thumb、fanart 用途和优先级正确。
- [ ] BigPic、ExtraPic、统一目录和相对影片目录均兼容。
- [ ] 列表加载缩略图，详情按需加载高清图。
- [ ] 智能卡图自动补全进入 Tasks。
- [ ] 重新识别、居中、居左、居右均可修正且不覆盖源图。
- [ ] 清理缓存只删除派生缓存，不删除源图和专用卡图。

### TP-FILES 重命名与整理

- [ ] 操作前显示旧路径、新路径和影响数量。
- [ ] 目标存在时绝不覆盖。
- [ ] 文件与数据库更新保持事务一致或可补偿回滚。
- [ ] 中途失败、权限不足、NAS 断线场景有可恢复结果。

### TP-TASKS 任务中心

- [ ] `Pending/Preparing/FetchingMetadata/DownloadingImages/WritingMetadata/WritingNfo/Retrying/Paused/Completed/Failed/Cancelled` 状态转换有效。
- [ ] 显示行为、状态、名称、进度和日期。
- [ ] 暂停、继续、取消、重试和日志工作正常。
- [ ] 应用重启后持久任务状态可恢复。
- [ ] 异常退出的同步任务记录“上次异常中断”并进入可重试队列，不永久卡在运行阶段。

## 6. 体验与扩展

### TP-UI（★★★★☆）

- [ ] 所有页面复用 AppShell、PageHeader、主题和公共组件。
- [ ] 深浅主题文字、边框、状态色和 Hover 可读。
- [ ] 100%/125%/150% 缩放无页面级横向溢出。
- [ ] 空态、加载态、Bridge 错误和部分数据状态完整。
- [ ] 键盘焦点、Enter/Space、Tooltip 和减少动态效果通过。

### TP-SETTINGS（★★★☆☆）

- [ ] 所有设置经过 Settings Service。
- [ ] 立即生效与需重启字段标记正确。
- [ ] 保存失败不伪装成功；重启后值保持。
- [ ] 敏感凭据不明文显示或存入普通 JSON。

### TP-BRIDGE-RELEASE（★★★★☆）

- [ ] Release 后台启动不显示控制台；Debug 保留控制台诊断。
- [ ] 文件日志轮转且不记录密钥、Cookie 或完整私人路径。
- [ ] 单实例、端口占用、Bridge 早退和崩溃均给出可理解诊断。
- [ ] 正常退出不残留 Bridge；异常退出后再次启动可恢复。
- [ ] 安装版只使用打包 Bridge/Migration，不回退到源码目录。

### TP-PLUGINS（★★☆☆☆）

- [ ] 插件声明版本、权限和兼容范围。
- [ ] 安装、启停、更新、卸载和失败隔离。
- [ ] 故障插件不阻止核心应用启动。

### TP-AI（0.6.0，★★★★★）

- [ ] AI 默认关闭；本地/云端和数据发送范围清楚。
- [ ] React 不直接调用模型；Provider 不直接访问数据库和文件系统。
- [ ] Provider、Model、PromptVersion、来源、置信度和用户决定可追踪。
- [ ] AI 只建议；应用前展示预览和影响范围。
- [ ] API Key 使用 Windows 安全凭据；路径、私人备注和图片默认不上传。
- [ ] AI 失败不影响普通搜索和媒体管理。
