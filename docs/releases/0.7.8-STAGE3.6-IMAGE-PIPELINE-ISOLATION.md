# v0.7.8 Stage 3.6 Image Pipeline Isolation

## Result

Fixed Stage 3.4 20-title manifest, local MetaTube (`127.0.0.1:8080`), 16 isolated runs: each has a new Bridge process, copied SQLite database and MediaStorage. All runs: 18 successful, 2 stable NoResult (`MD-0221`, `QQCM-002`), 0 failed, integrity `ok`, FK `0`.

## Modes

`Full` is normal temp-file, SKCodec probe, SHA-256 and persistent write. `Disabled` disables image requests. Drain reads response to discard; Buffer retains response bytes; Probe adds SKCodec header probe; Decode adds bitmap decode; DecodeAndHash adds SHA-256; FullWithoutFileWrite performs normal validation but deletes the temp file before persistent write.

## Conclusion

The only repeatable >=30% single-variable reduction is Disabled. Drain retains most private growth, buffer increases it, and removing persistent writes changes little. This narrows the likely stage to **HTTP response/content buffering or response-stream lifetime**, not probe, decode, hash, or final file write. **Root Cause Level 2.** The exact allocator/object remains unobserved, so no minimal production repair condition is met. Memory Gate remains blocked.
