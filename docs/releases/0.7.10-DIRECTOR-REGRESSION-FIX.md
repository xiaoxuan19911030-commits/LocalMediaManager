# v0.7.10 Director Optional Relation Regression Fix

## Scope

This change fixes one regression only: overwrite synchronization no longer deletes an existing Director relation when the provider omitted the optional Director field. Series shares the same generic overwrite path and is covered by the same safe condition. No provider protocol, schema, UI, image pipeline, search, or unrelated metadata behavior changed.

## Root Cause And Call Chain Audit

| File | Type | Method | Current behavior before fix | Risk | Fix |
|---|---|---|---|---|---|
| `MetadataProviders.cs` | model/evidence | `ProviderMetadata`, `ProviderMetadataEvidence.Attach` | `Director` and `Series` are nullable; `FieldSources` only contains non-empty observed fields. | Missing optional field was indistinguishable at the writer if only the nullable value was consulted. | Treat a non-empty value plus evidence entry as source-provided; preserve relations otherwise. Compatibility path permits non-empty legacy test/provider objects without `FieldSources`. |
| `MetadataSyncWorkflow.cs` | workflow | `MetadataSyncExecutor.ExecuteOneAsync` | Obtains provider metadata, invokes `MetadataWriteService.ApplyAsync`, then marks the task `Completed` only after the write succeeds. | A writer-side relation loss could be reported as a successful sync. | No status policy change required; writer failure still reaches `FailAsync`. |
| `MetadataSyncWorkflow.cs` | persistence | `MetadataWriteService.ApplyAsync` | `overwrite=true` unconditionally deleted `MovieDirectors` and `MovieSeries`, then inserted only non-empty values. | Omitted optional values erased historical relations. | Delete and insert Director/Series only when `SourceProvided` is true. |
| `MetadataSyncWorkflow.cs` | transaction | `MetadataWriteService.ApplyAsync` | Snapshot, movie update, relation deletion/insertion and applied snapshot use one SQLite transaction. | A failed insertion needed to retain this atomicity. | Existing transaction retained; regression test forces an insert failure and proves rollback. |
| `ProductionValidation/Program.cs` | validation | `ClassifyOptionalField` | Uses source evidence to classify Director/Series as optional and detects a real relation loss as `DataRegression`. | Incorrect writer behavior caused false data regression. | No change: omitted fields remain not-applicable; no relation is now lost. |
| `NfoWorkflow.cs` | import | NFO import relation loop / `AddRelationAsync` | Imports Actors, Tags, Genres, Series and Studio by additive `INSERT OR IGNORE`; it does not write Director and does not delete relations. | No reuse of the destructive path. | Audit only. |
| `ProductWriter.cs` | manual edit | public mutation methods | Manual editing exposes actor/tag/user-state operations, not Director or Series relation replacement. | No reuse of the destructive path. | Audit only. |

`SourceProvided` is intentionally conservative: a null/blank value, or a field absent from a populated `FieldSources` map, is not a clear request. The current model cannot safely represent an explicit empty optional relation, so synchronization preserves history in that case.

## Before And After

Before: overwrite synchronization deleted Director/Series relations before checking whether the provider provided their values. THU-063 could finish `Completed` after its historical Director was lost.

After: overwrite synchronization replaces Director/Series only for an explicit non-empty provider value. Omitted values preserve existing relations and do not generate warnings, `NoResult`, missing metadata, or `DataRegression`.

## Transaction Scope

`MetadataWriteService.ApplyAsync` starts one SQLite transaction before snapshot creation and commits only after movie values, optional relations, image rows and the applied snapshot succeed. The Director write-failure test installs a SQLite abort trigger after an old relation; the attempted replacement throws, transaction disposal rolls back, the old relation remains, and no new relation survives. `MetadataSyncExecutor` maps such a writer exception to `Failed`, rather than `Completed`.

Risk is low: the condition only narrows replacement of two optional relations during overwrite synchronization.
