## Conclusion

JavBus is currently usable as a fill-missing fallback behind MetaTube, with an important operational requirement: a valid locally configured Cookie is required. The configured path returned real movie pages for 10/10 test numbers. An anonymous request was redirected to the JavBus driver verification page and must be classified as `AuthenticationRequired`, not as a movie result.

The integration keeps the existing Provider pipeline. It does not add a second Writer or Merge path:

```text
MetaTube -> JavBus (only when a supported field is missing) -> fill-missing Merge -> existing Writer
```

## Parser Result

The existing field selectors parsed all 10 real pages, so their field extraction rules did not require structural replacement. The parser boundary did require two correctness fixes:

1. Detect driver-verification and Cloudflare challenge pages before parsing.
2. Reuse the validated Search HTML for Detail parsing through a two-minute, 64-entry, Cookie-scoped in-memory cache.

The second change reduces one JavBus Search + Detail flow from two identical HTTP downloads to one. Cached HTML is consumed once and is never persisted.

```text
Raw HTML -> blocked-page guard -> JavBusParser -> ProviderMetadataEvidence -> ProviderResult -> Merge Preview
```
