## 执行结论

当前最大瓶颈不是 Provider → Merge 普遍丢字段，而是统计层和资源状态层：

1. Dashboard 把 944 部 Local 和 6 部未分配影片纳入 Standard 元数据分母，导致演员、标签、图片和 NFO 覆盖率被系统性压低。
2. Provider 标签写入 `Genres/MovieGenres`，Dashboard 与 Metadata Health 却读取 `Tags/MovieTags`。Standard 的真实 Provider 标签覆盖为 1112 / 1370 (81.2%)，Dashboard 口径仅为 511 / 2320 (22.0%)。
3. 文件状态存在双向不一致：2320 部活动影片的图片记录指向缺失文件 636 条，NFO 状态存在但实体文件缺失 41 部；MediaStorage 中另有 1245 个有效元数据资产未被数据库状态登记。
4. Standard 中有 176 部的持久化 `Movies.Code` 与当前规则库重识别结果不一致，其中 127 部 Code 仍含 `+标签`；它们应先复核番号/文件关联，不能直接归因于 Provider。

因此，v0.7.4-A 应先修统计分母、标签关系语义与文件状态/资源关联。完成这一步即可显著修正覆盖率，不应先重跑 1300 多部影片。
