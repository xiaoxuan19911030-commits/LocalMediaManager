## 5. Handles, Threads, Caches, And Pools

- Handles rose during work but returned from 811/799 at batch completion to 765/770 after Full GC; they did not grow linearly across the two batches.
- Threads returned to the 49-54 range and did not accumulate.
- Provider cache and provider history entries remained zero in all runtime snapshots.
- `SqliteConnection.ClearAllPools()` reduced handles from 765 to 716 immediately after batch 1, while private commit changed from 317.2 to 317.7 MiB. SQLite pooled handles are not the primary retained-private-memory source.
- Active TCP connections, open-file count, active SQLite connections, and open streams are `Not Available` from the current runtime APIs. No values were inferred.

## 6. Native Heap Diagnostic Limitation

The validation-only HeapWalk summary enumerated seven process heaps, but its `BusyBytes` saturated at `Int64.MaxValue`. That aggregate is not credible as an allocation-size measurement and is not used for allocator, module, or call-site attribution. No conclusion is drawn from it.

## 7. Synchronization Correctness

Both batches completed with the same environmental Provider regression: 75 completed, 2 completed with warnings, and 23 `NoResult` tasks. This differs from the Stage 3 accepted 97 eligible Provider successes, so this run is not a synchronization-correctness pass.

The isolation and data-integrity checks that did run remained clean in both batches: `PRAGMA integrity_check = ok`, foreign-key errors 0, protected user-data changes 0, duplicate relations/resources 0, missing registered resources 0, and unregistered files 0.

## 8. Root Cause Level

`Level 3 - Process and Memory Category Identified`

The growing process is the .NET Bridge, and the persistent category is committed `MEM_PRIVATE`. The evidence does not identify a specific native allocator, module, resource-download call site, SQLite allocation, or runtime cache. The controlled result rules out managed heap growth, bridge-visible Provider caches, thread accumulation, and SQLite pool handles as the primary cause, but it does not prove the remaining native subsystem.

## 9. Fix Decision

`Additional Investigation Required`

No production synchronization, Provider, image, NFO, SQLite, Tauri, or UI behavior was changed. No minimum production fix is justified before Level 2 evidence identifies a subsystem. The only code change is validation-harness sampling granularity.
