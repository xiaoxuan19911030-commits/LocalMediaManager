# Local Media Manager v0.7.4-C Metadata Completion

## Scope

v0.7.4-C adds a Standard-only Metadata Completion workflow. It analyzes missing fields, persists a Dry Run plan, requires an exact confirmation token, calls only Providers that can contribute a planned field, and merges with fill-empty-only protection.

This report records source, tests, builds, and a Dry Run against a SQLite backup of the production database. No production completion execution, Provider request, metadata write, image download, NFO write, deployment, or production database mutation was performed.

## Safety model

- Standard movies only; Local and unassigned movies never enter the plan.
- Missing media, low-confidence numbers, multiple candidates, Code conflicts, locked images, and locked/user NFO are excluded or protected.
- Dry Run performs no Provider calls.
- The remote Provider API may return a full metadata document, but LMM discards non-target fields before Merge.
- Existing metadata, images, actors, genres, NFO, user tags, ratings, favorites, and playback state are not overwritten.
- Default concurrency is 4; execution supports pause, persisted checkpoint resume, three attempts with exponential backoff, and Provider-specific throttling.
- Session rollback restores database fields and relations recorded in `OperationAudit`. Physical files are retained and never deleted by rollback.
- The workflow reuses `Tasks`, `TaskLogs`, `OperationAudit`, `MetadataSyncSnapshots`, `MetadataWriteService`, `MediaStoragePathResolver`, and the v0.7.4-A health definition. No schema migration was added.

## Provider capabilities

| Provider | Planned capabilities | Default field priority role |
|---|---|---|
| JavBus | Actors, Genres, release date, description, director, studio, series, Poster/Fanart, NFO source metadata | Text and relation fields |
| MetaTube | Poster, Fanart, NFO source metadata, series, actors, genres, date, director, studio, description | Images, NFO, series; fallback for text |
| MDC-NG | Supplementary text, relations, images, and NFO source metadata | Fallback after field-specific preferred sources |

The per-item Provider plan contains the fallback chain. Request estimates count only each field's first enabled Provider. Execution stops requesting later Providers as soon as all target fields are satisfied.

## Automated tests

Twelve focused tests cover:

1. Dry Run makes zero Provider calls and writes no metadata.
2. Provider Capability routes actor completion to JavBus first.
3. Field-level completion does not overwrite an existing description.
4. Existing target fields are not requested.
5. Transient failures use exponential retry.
6. Same-Provider calls honor the rate-limit gate.
7. A paused session resumes from its persisted plan.
8. Session rollback restores database associations.
9. Metadata Health is recalculated after completion.
10. Repeated execution is idempotent.
11. Provider no-result is classified without writes.
12. Local movies are excluded.
